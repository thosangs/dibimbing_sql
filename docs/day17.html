Diagnostik Awal: Kenali Data

Mulai dengan pertanyaan sederhana untuk mendapat gambaran landscape — volume, trend, distribusi. Semua bisa dijawab dengan GROUP BY + agregasi dasar, kadang dengan date truncation untuk binning waktu.

// Teknik yang Dipakai

E1 Daily trend    → DATE_TRUNC('day', rental_date) + COUNT(*)
E2 Top 10 films   → JOIN inventory + rental, GROUP BY film, ORDER BY DESC LIMIT 10
E3 Monthly payments → DATE_TRUNC('month', payment_date) + SUM(amount)
E4 New customers  → MIN(rental_date) per customer → GROUP BY bulan
E5 Rentals/category → JOIN chain: category→film_category→film→inventory→rental
E6 Avg duration   → AVG(return_date - rental_date) per category
E7 Top cities     → JOIN chain: rental→customer→address→city, GROUP BY city
E8 Active 30d     → MAX(rental_date) sebagai "last date in data" - 30 days
Contoh: E4 — New Customers Per Month
-- Definisi "new customer": bulan pertama mereka pernah renting
WITH first_rental AS (
  SELECT customer_id,
         DATE_TRUNC('month', MIN(rental_date)) AS cohort_month
  FROM rental
  GROUP BY customer_id
)
SELECT cohort_month,
       COUNT(*) AS new_customers
FROM first_rental
GROUP BY cohort_month
ORDER BY cohort_month;
Contoh: E8 — Active Customers Last 30 Days
-- "Last 30 days" = 30 hari sebelum tanggal rental terakhir di data
WITH data_end AS (
  SELECT MAX(rental_date) AS max_date FROM rental
)
SELECT COUNT(DISTINCT r.customer_id) AS active_customers
FROM rental r, data_end
WHERE r.rental_date >= data_end.max_date - INTERVAL '30 days';

Cohort Retention & Churn Analysis

Cohort analysis mengelompokkan customer berdasarkan kapan mereka pertama kali aktif, lalu melacak retention mereka di bulan-bulan berikutnya. Churn didefinisikan sebagai customer yang aktif di bulan N-1 tapi tidak aktif di bulan N. Keduanya membutuhkan perbandingan antar-bulan yang umumnya menggunakan CTE berlapis + conditional aggregation.

Teknik: M1 — Cohort Retention
-- Cohort = bulan pertama renting; retention = renting di bulan +1, +2, +3
WITH cohorts AS (
  SELECT customer_id,
         DATE_TRUNC('month', MIN(rental_date)) AS cohort_month
  FROM rental GROUP BY customer_id
),
activity AS (
  SELECT r.customer_id,
         DATE_TRUNC('month', r.rental_date) AS active_month
  FROM rental r GROUP BY 1, 2
),
joined AS (
  SELECT c.cohort_month, a.active_month,
         -- bulan berapa sejak cohort (0 = bulan pertama, 1 = bulan berikutnya, dst)
         EXTRACT(MONTH FROM AGE(a.active_month, c.cohort_month))::int AS months_since
  FROM cohorts c
  JOIN activity a USING (customer_id)
  WHERE a.active_month >= c.cohort_month
    AND months_since BETWEEN 0 AND 3
)
SELECT cohort_month,
  COUNT(DISTINCT CASE WHEN months_since = 0 THEN customer_id END) AS m0_active,
  COUNT(DISTINCT CASE WHEN months_since = 1 THEN customer_id END) AS m1_active,
  COUNT(DISTINCT CASE WHEN months_since = 2 THEN customer_id END) AS m2_active,
  COUNT(DISTINCT CASE WHEN months_since = 3 THEN customer_id END) AS m3_active
FROM joined
GROUP BY cohort_month
ORDER BY cohort_month;

COUNT(DISTINCT CASE WHEN ... THEN customer_id END) adalah pola "pivot via conditional aggregation" — menghitung distinct customer yang memenuhi kondisi tertentu dalam satu GROUP BY, tanpa PIVOT syntax yang tidak ada di PostgreSQL.

Teknik: M2 — Monthly Churn Rate
-- Churn: aktif bulan lalu, tidak aktif bulan ini
WITH monthly_active AS (
  SELECT customer_id,
         DATE_TRUNC('month', rental_date) AS active_month
  FROM rental GROUP BY 1, 2
),
with_prev AS (
  SELECT customer_id, active_month,
         -- apakah customer ini aktif bulan sebelumnya?
         LAG(active_month) OVER (
           PARTITION BY customer_id ORDER BY active_month
         ) AS prev_month
  FROM monthly_active
)
SELECT active_month,
  COUNT(*) AS active_this_month,
  -- churned: prev_month ada tapi bukan bulan sebelumnya (ada gap)
  COUNT(CASE WHEN prev_month IS NOT NULL
              AND active_month != prev_month + INTERVAL '1 month'
         THEN 1 END) AS churned,
  ROUND(
    100.0 * COUNT(CASE WHEN prev_month IS NOT NULL
                        AND active_month != prev_month + INTERVAL '1 month'
                   THEN 1 END)
    / NULLIF(COUNT(*), 0), 1
  ) AS churn_pct
FROM with_prev
GROUP BY active_month
ORDER BY active_month
LIMIT 6;

Rolling Windows & Contribution Curves

7-day rolling sum membutuhkan frame ROWS BETWEEN 6 PRECEDING AND CURRENT ROW — tapi pertama harus ada data harian per kategori. Cumulative contribution (top N% of rentals) menggunakan running SUM dibagi total — berguna untuk Pareto analysis: "top 20% film menghasilkan 80% rental".

Teknik: H1 — 7-Day Rolling Rentals Per Category
-- Step 1: daily rentals per category
WITH daily_cat AS (
  SELECT
    DATE_TRUNC('day', r.rental_date)::date AS rental_day,
    c.name AS category,
    COUNT(r.rental_id) AS daily_rentals
  FROM rental r
  JOIN inventory i      ON i.inventory_id = r.inventory_id
  JOIN film f           ON f.film_id = i.film_id
  JOIN film_category fc ON fc.film_id = f.film_id
  JOIN category c       ON c.category_id = fc.category_id
  GROUP BY 1, 2
)
-- Step 2: 7-day rolling sum dengan ROWS frame
SELECT
  rental_day, category, daily_rentals,
  SUM(daily_rentals) OVER (
    PARTITION BY category
    ORDER BY rental_day
    ROWS BETWEEN 6 PRECEDING AND CURRENT ROW  -- 7 hari termasuk hari ini
  ) AS rentals_7d
FROM daily_cat
ORDER BY category, rental_day;
Teknik: H2 — Cumulative % (Pareto / Top N Films)
-- Top 5 films by rentals dan cumulative % terhadap total
WITH film_totals AS (
  SELECT f.film_id, f.title,
         COUNT(r.rental_id) AS total_rentals
  FROM film f
  JOIN inventory i ON i.film_id = f.film_id
  JOIN rental r    ON r.inventory_id = i.inventory_id
  GROUP BY f.film_id, f.title
),
ranked AS (
  SELECT *,
    SUM(total_rentals) OVER (ORDER BY total_rentals DESC
                              ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS running_sum,
    SUM(total_rentals) OVER () AS grand_total,
    ROW_NUMBER() OVER (ORDER BY total_rentals DESC) AS rn
  FROM film_totals
)
SELECT film_id, title, total_rentals,
       ROUND(100.0 * running_sum / grand_total, 1) AS cumulative_pct
FROM ranked
WHERE rn <= 5
ORDER BY rn;

// Pola Umum: CTE Stack untuk Query Kompleks

Query kompleks = tumpukan CTE yang masing-masing menjawab satu pertanyaan:

WITH
  raw_data AS (
    -- Step 1: ambil data mentah dengan JOIN yang diperlukan
    SELECT ...
  ),
  aggregated AS (
    -- Step 2: agregasi atau window
    SELECT ..., SUM() OVER (...) FROM raw_data
  ),
  filtered AS (
    -- Step 3: filter hasil window (tidak bisa WHERE langsung)
    SELECT * FROM aggregated WHERE ...
  )
SELECT * FROM filtered ORDER BY ...;

Setiap CTE = satu langkah logis = mudah di-debug per bagian

Untuk debug query CTE berlapis: jalankan setiap CTE secara terpisah sebagai query standalone. Ganti WITH name AS (...) SELECT * FROM next_cte dengan SELECT * FROM (isi CTE) t untuk memverifikasi output per langkah.

// Decision Tree: Kapan Pakai Apa

Pertanyaan                              → Teknik
────────────────────────────────────────┼──────────────────────────────────────
"Berapa total/rata-rata per grup?"      → GROUP BY + aggregate
"Filter berdasarkan hasil aggregate?"   → HAVING (bukan WHERE)
"Nomor urut per grup?"                  → ROW_NUMBER() OVER (PARTITION BY ...)
"Top N per grup?"                       → RANK/DENSE_RANK + filter di CTE
"Nilai baris sebelumnya/sesudahnya?"    → LAG() / LEAD()
"Running total?"                        → SUM() OVER (UNBOUNDED PRECEDING AND CURRENT ROW)
"Moving average N hari?"                → AVG() OVER (ROWS BETWEEN N-1 PRECEDING AND CURRENT ROW)
"Query terlalu kompleks/susah dibaca?"  → Pecah jadi beberapa CTE
"Churn: aktif bulan lalu, tidak bulan ini?" → LAG(active_month) + kondisi gap
"Cohort: kapan pertama aktif?"          → MIN(date) per customer → DATE_TRUNC(month)
