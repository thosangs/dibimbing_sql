Day 14 / 17

Basic & Intermediate SQL

Filtering, agregasi, conditional logic, semua jenis JOIN, dan UNION — building blocks query SQL yang dipakai sehari-hari di analytics.

WHERE / IN / BETWEEN GROUP BY / HAVING CASE WHEN JOIN Types UNION / UNION ALL
// 01 — Filtering

WHERE, IN, BETWEEN, LIKE

Clause WHERE memfilter baris sebelum agregasi — PostgreSQL mengevaluasi kondisi per-baris saat table scan. IN adalah sugar syntax untuk OR yang panjang — planner biasanya mengonversinya ke hash lookup. BETWEEN inklusif di kedua ujung. LIKE menggunakan pattern matching: % untuk sembarang string, _ untuk satu karakter. ILIKE adalah case-insensitive variant yang spesifik PostgreSQL.

examples/filtering.sql
-- Film dengan rental_rate tinggi DAN durasi pendek
SELECT f.film_id, f.title, f.rental_rate, f.length
FROM film f
WHERE f.rental_rate > 3.99
  AND f.length < 50
ORDER BY f.rental_rate DESC, f.film_id
LIMIT 20;

-- IN: film dari kategori Action, Comedy, atau Family
SELECT f.film_id, f.title, c.name AS category
FROM film f
JOIN film_category fc ON fc.film_id = f.film_id
JOIN category c       ON c.category_id = fc.category_id
WHERE c.name IN ('Action', 'Comedy', 'Family')
ORDER BY f.film_id;

-- BETWEEN: pembayaran dalam rentang tanggal (inklusif)
SELECT p.payment_id, p.customer_id, p.amount, p.payment_date
FROM payment p
WHERE p.payment_date BETWEEN '2005-05-01' AND '2005-06-01'
ORDER BY p.payment_date;

-- LIKE: customer yang namanya diawali 'D'
SELECT c.first_name, c.last_name
FROM customer c
WHERE c.first_name LIKE 'D%';  -- % = sembarang karakter (0+)

Untuk kolom TIMESTAMPTZ, gunakan half-open range (>= start AND < end) daripada BETWEEN — BETWEEN inklusif di ujung atas bisa melewatkan baris di hari berikutnya jam 00:00:00.

// 02 — Aggregation

GROUP BY, HAVING, Aggregate Functions

Aggregate functions (COUNT, SUM, AVG, MAX, MIN) mereduksi banyak baris menjadi satu nilai per grup. GROUP BY mendefinisikan batas grup — semua kolom di SELECT yang bukan aggregate harus ada di GROUP BY. HAVING memfilter setelah agregasi (berbeda dengan WHERE yang memfilter sebelum) — ini satu-satunya cara filter berdasarkan hasil aggregate.

examples/aggregation.sql
-- Statistik keseluruhan payment
SELECT
  COUNT(*)        AS total_transactions,
  AVG(amount)     AS average_payment,
  SUM(amount)     AS total_revenue,
  MAX(amount)     AS max_payment,
  MIN(amount)     AS min_payment
FROM payment;

-- Grup per customer: total belanja
SELECT
  p.customer_id,
  COUNT(*)        AS num_payments,
  SUM(p.amount)   AS total_spent,
  AVG(p.amount)   AS avg_payment
FROM payment p
GROUP BY p.customer_id
ORDER BY total_spent DESC
LIMIT 20;

-- HAVING: hanya customer dengan 30+ pembayaran
SELECT
  p.customer_id,
  COUNT(*)        AS num_payments,
  SUM(p.amount)   AS total_spent
FROM payment p
GROUP BY p.customer_id
HAVING COUNT(*) >= 30     -- filter SETELAH GROUP BY
ORDER BY total_spent DESC;

-- Agregasi per bulan menggunakan DATE_TRUNC
SELECT
  date_trunc('month', p.payment_date) AS month,
  COUNT(*)        AS num_transactions,
  SUM(p.amount)   AS revenue
FROM payment p
GROUP BY date_trunc('month', p.payment_date)
ORDER BY month;

WHERE vs HAVING: WHERE dieksekusi sebelum GROUP BY (mengurangi baris yang diagregasi), HAVING dieksekusi sesudah GROUP BY (memfilter hasil agregasi). Gunakan WHERE jika bisa — lebih efisien karena mengurangi data lebih awal.

// 03 — Conditional Logic

CASE WHEN, COALESCE, GREATEST/LEAST

CASE WHEN adalah conditional expression — bukan statement — sehingga bisa dipakai di SELECT, WHERE, ORDER BY, dan GROUP BY. COALESCE mengembalikan argumen pertama yang bukan NULL — idiom paling umum untuk default value. GREATEST/LEAST membandingkan daftar nilai dan mengembalikan yang terbesar/terkecil.

examples/conditional.sql
-- CASE WHEN: kategorisasi durasi film
SELECT
  f.title,
  f.length,
  CASE
    WHEN f.length <= 50              THEN 'Short'
    WHEN f.length > 50 AND f.length <= 120 THEN 'Medium'
    ELSE 'Long'
  END AS movie_length_category
FROM film f;

-- COALESCE: tampilkan address2 atau 'N/A' jika NULL
SELECT
  c.customer_id, c.first_name, c.last_name,
  COALESCE(a.address2, 'N/A') AS address2_label
FROM customer c
JOIN address a ON a.address_id = c.address_id
ORDER BY c.customer_id
LIMIT 50;

-- GREATEST/LEAST: clamp nilai payment
SELECT
  p.payment_id,
  p.amount,
  GREATEST(p.amount, 0)      AS amount_floor_zero,  -- tidak boleh negatif
  LEAST(p.amount, 10.00)     AS amount_cap_10        -- maksimal 10
FROM payment p
LIMIT 50;

-- CASE untuk tier payment
SELECT
  p.payment_id, p.amount,
  CASE
    WHEN p.amount < 2 THEN 'Bronze'
    WHEN p.amount < 5 THEN 'Silver'
    WHEN p.amount < 8 THEN 'Gold'
    ELSE 'Platinum'
  END AS payment_tier
FROM payment p
LIMIT 50;

CASE dievaluasi short-circuit: kondisi pertama yang true langsung mengembalikan nilai, kondisi berikutnya tidak dievaluasi. COALESCE(a, b, c) equivalen dengan CASE WHEN a IS NOT NULL THEN a WHEN b IS NOT NULL THEN b ELSE c END.

// 04 — JOINs

INNER, LEFT, RIGHT, FULL OUTER, CROSS JOIN

JOIN menggabungkan baris dari dua tabel berdasarkan kondisi. INNER JOIN hanya mengembalikan pasangan yang cocok di kedua sisi. LEFT JOIN mengembalikan semua baris kiri + pasangan dari kanan (NULL jika tidak ada). FULL OUTER JOIN mengembalikan semua baris dari kedua sisi, NULL di sisi yang tidak punya pasangan. CROSS JOIN adalah Cartesian product — setiap baris kiri dipasangkan dengan setiap baris kanan.

examples/joins.sql
-- INNER JOIN: customer + payment mereka
SELECT c.customer_id, c.first_name, c.last_name,
       p.payment_id, p.amount, p.payment_date
FROM customer c
INNER JOIN payment p ON c.customer_id = p.customer_id
ORDER BY c.customer_id, p.payment_date;

-- LEFT JOIN: semua kategori, termasuk yang tidak punya film
SELECT c.category_id, c.name AS category_name,
       f.film_id, f.title
FROM category c
LEFT JOIN film_category fc ON fc.category_id = c.category_id
LEFT JOIN film f           ON f.film_id = fc.film_id
ORDER BY c.category_id, f.film_id NULLS LAST;

-- FULL OUTER JOIN: semua kategori DAN semua film (meski tidak terhubung)
SELECT c.category_id, c.name AS category_name,
       f.film_id, f.title
FROM category c
FULL OUTER JOIN film_category fc ON fc.category_id = c.category_id
FULL OUTER JOIN film f           ON f.film_id = fc.film_id
ORDER BY COALESCE(c.category_id, -1), COALESCE(f.film_id, -1);

-- CROSS JOIN: Cartesian product (3 kategori × 3 film = 9 baris)
SELECT c.category_id, c.name AS category_name,
       f.film_id, f.title
FROM (SELECT * FROM category ORDER BY category_id LIMIT 3) c
CROSS JOIN (SELECT * FROM film ORDER BY film_id LIMIT 3) f
ORDER BY c.category_id, f.film_id;

// 05 — Set Operations

UNION vs UNION ALL

UNION ALL menggabungkan result set tanpa deduplication — lebih cepat karena tidak perlu sorting/hashing. UNION (tanpa ALL) secara implisit melakukan DISTINCT pada gabungan — membuang duplikat tapi memerlukan sort atau hash extra. Gunakan UNION ALL by default kecuali duplikat memang perlu dibuang — lebih efisien dan intent lebih eksplisit.

examples/union.sql
-- UNION ALL: gabungkan nama customer DAN judul film (dengan duplikat)
-- Kolom harus sama jumlah dan kompatibel tipenya
SELECT first_name AS entity_name FROM customer
UNION ALL
SELECT title AS entity_name FROM film;

-- UNION: sama tapi buang duplikat (ada nama customer = judul film?)
SELECT first_name AS entity_name FROM customer
UNION
SELECT title AS entity_name FROM film;

Kedua query membutuhkan kolom yang sama jumlah dan kompatibel tipe-nya. Nama kolom diambil dari SELECT pertama. UNION implisit melakukan ORDER BY untuk deduplication — ini sebabnya lebih lambat dari UNION ALL.
