Window Functions

// 01 — Anatomy

OVER Clause: Cara Kerjanya

Window function tidak collapse baris seperti GROUP BY — setiap baris masih ada dalam output, tapi fungsi dihitung terhadap sekumpulan baris terkait (the "window"). PARTITION BY mendefinisikan batas grup (seperti GROUP BY tapi tanpa collapse). ORDER BY mendefinisikan urutan dalam tiap partition untuk fungsi yang order-sensitive. FRAME CLAUSE mendefinisikan subset baris dalam partition yang digunakan untuk kalkulasi (default berbeda-beda per fungsi).

// Anatomy OVER Clause

SUM(amount) OVER (
  PARTITION BY customer_id      ← batas grup: satu window per customer
  ORDER BY payment_date         ← urutan dalam window (untuk running total)
  ROWS BETWEEN                  ← frame: subset baris yang dihitung
    UNBOUNDED PRECEDING          ← dari baris pertama dalam partition...
    AND CURRENT ROW              ← ...sampai baris ini
)

Tanpa PARTITION BY → satu window = seluruh tabel
Tanpa ORDER BY     → frame default = seluruh partition (untuk aggregates)
Tanpa FRAME        → default: RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW

Frame options:
  ROWS BETWEEN 2 PRECEDING AND CURRENT ROW  → 3 baris terakhir (by count)
  RANGE BETWEEN ...                          → by value (tipe data)
  GROUPS BETWEEN ...                         → by distinct value group
// 02 — Ranking Functions

ROW_NUMBER, RANK, DENSE_RANK, NTILE

NTILE(n) membagi baris dalam partition menjadi n bucket seukuran mungkin — berguna untuk kuartil, desil, atau percentile. Bucket pertama mendapat baris ekstra jika tidak habis dibagi rata. ROW_NUMBER, RANK, DENSE_RANK sudah dibahas di Day 15 — di sini kita pakai semuanya bersamaan untuk membandingkan.

examples/ranking.sql
-- Semua ranking function sekaligus: film per kategori by jumlah rental
WITH film_rentals AS (
  SELECT c.name AS category,
         f.film_id, f.title,
         COUNT(r.rental_id) AS rentals
  FROM category c
  JOIN film_category fc ON fc.category_id = c.category_id
  JOIN film f           ON f.film_id = fc.film_id
  JOIN inventory i      ON i.film_id = f.film_id
  JOIN rental r         ON r.inventory_id = i.inventory_id
  GROUP BY c.name, f.film_id, f.title
)
SELECT category, title, rentals,
  ROW_NUMBER() OVER (PARTITION BY category ORDER BY rentals DESC) AS row_num,
  RANK()       OVER (PARTITION BY category ORDER BY rentals DESC) AS rank_val,
  DENSE_RANK() OVER (PARTITION BY category ORDER BY rentals DESC) AS dense_rank_val,
  NTILE(4)     OVER (PARTITION BY category ORDER BY rentals DESC) AS quartile
FROM film_rentals
ORDER BY category, rentals DESC, title
LIMIT 50;

NTILE(4) membagi film per kategori menjadi 4 quartile — Q1 adalah 25% teratas by rentals. Sangat berguna untuk segmentasi: "top 25% film terlaris per kategori".

// 03 — Navigation Functions

LAG, LEAD, FIRST_VALUE, LAST_VALUE, NTH_VALUE

LAG(col, n) mengakses nilai dari n baris sebelumnya dalam window — tanpa self-join. LEAD(col, n) mengakses n baris ke depan. Keduanya sangat berguna untuk menghitung selisih antar event (days since last purchase, MoM growth). FIRST_VALUE / LAST_VALUE mengakses baris pertama/terakhir dalam frame — perhatikan bahwa frame default untuk LAST_VALUE adalah CURRENT ROW, sehingga perlu menambahkan ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING untuk mendapat nilai akhir partition.

examples/navigation.sql
-- LAG/LEAD/FIRST_VALUE/LAST_VALUE per customer
WITH r AS (
  SELECT customer_id, rental_id, rental_date,
    -- baris sebelum dan sesudahnya
    LAG(rental_date)  OVER (PARTITION BY customer_id ORDER BY rental_date) AS prev_rental_date,
    LEAD(rental_date) OVER (PARTITION BY customer_id ORDER BY rental_date) AS next_rental_date,
    -- baris pertama dan terakhir dalam partition
    FIRST_VALUE(rental_date) OVER (
      PARTITION BY customer_id ORDER BY rental_date
    ) AS first_rental_date,
    LAST_VALUE(rental_date) OVER (
      PARTITION BY customer_id ORDER BY rental_date
      ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING  -- frame eksplisit!
    ) AS last_rental_date,
    -- baris ke-2
    NTH_VALUE(rental_date, 2) OVER (
      PARTITION BY customer_id ORDER BY rental_date
      ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
    ) AS second_rental_date
  FROM rental
)
SELECT customer_id, rental_id, rental_date,
       prev_rental_date, next_rental_date,
       first_rental_date, last_rental_date, second_rental_date
FROM r
ORDER BY customer_id, rental_date
LIMIT 100;

Tanpa frame eksplisit, LAST_VALUE mengembalikan nilai baris saat ini (bukan akhir partition) karena default frame adalah RANGE UNBOUNDED PRECEDING AND CURRENT ROW. Selalu tambahkan ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING untuk LAST_VALUE.

// 04 — Aggregate Windows

Running Total, Moving Average, Partition Aggregate

Aggregate functions standar (SUM, AVG, COUNT, MAX, MIN) bisa dipakai sebagai window function dengan OVER(). Running total menjumlahkan semua baris dari awal partition sampai baris saat ini. Moving average menggunakan frame dengan ukuran tetap (mis. 3 baris terakhir). Partition aggregate menghitung total untuk seluruh grup dan menempel di setiap baris — tanpa GROUP BY.

examples/aggregates.sql
-- Running total, moving avg, dan partition aggregate dalam satu query
WITH p AS (
  SELECT customer_id, payment_id, payment_date, amount FROM payment
)
SELECT
  customer_id, payment_id, payment_date, amount,

  -- Moving average: rata-rata 3 payment terakhir (ROWS frame)
  AVG(amount) OVER (
    PARTITION BY customer_id
    ORDER BY payment_date
    ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
  ) AS avg_last_3,

  -- Running count: berapa payment sampai saat ini
  COUNT(*) OVER (
    PARTITION BY customer_id
    ORDER BY payment_date
    ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
  ) AS cumulative_count,

  -- Running total: total belanja terakumulasi
  SUM(amount) OVER (
    PARTITION BY customer_id
    ORDER BY payment_date
    ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
  ) AS running_total,

  -- Partition total: total semua payment customer ini (sama di tiap baris)
  SUM(amount) OVER (PARTITION BY customer_id) AS total_per_customer,

  -- Max/min dalam partition
  MAX(amount) OVER (PARTITION BY customer_id) AS max_amount_for_customer,
  MIN(amount) OVER (PARTITION BY customer_id) AS min_amount_for_customer
FROM p
ORDER BY customer_id, payment_date
LIMIT 100;

// Frame Clause: ROWS vs RANGE vs GROUPS

Frame Type  | Unit                    | Use Case
────────────┼─────────────────────────┼────────────────────────────────
ROWS        | Physical rows (by count)| Rolling N periods, N-row MA
RANGE       | Value range (data type) | "Same day", "same value" groups
GROUPS      | Peer groups             | Group-based accumulation

Contoh pada payment table per customer, ORDER BY payment_date:

ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
→ sum 3 baris terakhir by count, terlepas dari tanggalnya

RANGE BETWEEN CURRENT ROW AND CURRENT ROW
→ sum semua baris yang punya timestamp PERSIS sama
  (berguna untuk payment yang terjadi di momen yang sama)

GROUPS BETWEEN 1 PRECEDING AND CURRENT ROW
→ sum baris dari group sebelumnya + group saat ini
  (1 group = semua baris dengan nilai ORDER BY yang sama)
// 05 — Frame Clause Detail

ROWS, RANGE, GROUPS — Perbedaan Nyata

examples/window_frame.sql
-- ROWS frame: sum berdasarkan hitungan baris
SELECT customer_id, payment_id, payment_date, amount,
  SUM(amount) OVER (
    PARTITION BY customer_id
    ORDER BY payment_date
    ROWS BETWEEN 2 PRECEDING AND CURRENT ROW  -- 3 baris terakhir
  ) AS sum_rows_last_2
FROM payment
ORDER BY customer_id, payment_date
LIMIT 100;

-- RANGE frame: sum semua payment dengan timestamp yang sama
SELECT customer_id, payment_id, payment_date::date AS day, amount,
  SUM(amount) OVER (
    PARTITION BY customer_id
    ORDER BY payment_date
    RANGE BETWEEN CURRENT ROW AND CURRENT ROW  -- exact same timestamp
  ) AS sum_same_timestamp_range
FROM payment
ORDER BY customer_id, payment_date
LIMIT 100;

ROWS adalah yang paling predictable — gunakan ini by default untuk rolling windows. RANGE berguna untuk "semua event di hari yang sama" tapi memerlukan tipe data yang bisa dibandingkan dengan nilai numerik atau interval.

// 06 — Business Case Study

Studi Kasus: dvdrental Analytics

Semua pertanyaan di bawah menggunakan window functions — dari high-value customer identification hingga churn risk detection.

Case 1

High-Value Customers

Top 10% customer by total payment yang rented di minimal 3 bulan berbeda — NTILE + COUNT DISTINCT.

Case 2

Category Momentum

Rentals H1 vs H2 2005 per kategori, pct_change — conditional aggregation + simple division.

Case 3

Star Performers

Actor dengan rental tertinggi per release year — RANK() OVER (PARTITION BY release_year).

Case 4

Lifetime Spend Trajectory

Running total per payment per customer — SUM OVER (UNBOUNDED PRECEDING AND CURRENT ROW).

Case 7

Time-to-Next-Rental

Gap antar rental per customer — LEAD(rental_date) - rental_date sebagai churn signal.

Case 10

Frame Sensitivity

Bandingkan ROWS vs RANGE vs GROUPS pada dataset yang sama — edge cases frame clause.
